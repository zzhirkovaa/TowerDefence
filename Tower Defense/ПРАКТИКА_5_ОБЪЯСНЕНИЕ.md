# Пятая практическая: здоровье и починка башни

## Что требует задание

Нужно реализовать хотя бы два сценария взаимодействия между GameObject и Entity и объяснить выбранный способ. Здесь сделаны три сценария:

1. **Entity → GameObject:** ECS хранит HP башни. `TowerHealthPanel` читает его и показывает на Canvas.
2. **GameObject → Entity:** кнопка «Починить башню (+20)» вызывает метод `RepairTower`, который меняет компонент HP у ECS-башни.
3. **Entity → GameObject через событие:** когда HP достигает нуля, `TowerDefeatSystem` один раз вызывает делегат. `TowerDefeatPanel` получает вызов и показывает панель поражения.

Враг, достигший башни, снимает 10 HP и исчезает. Это взаимодействие **Entity → Entity внутри ECS**; само по себе оно не является одним из двух сценариев связи с GameObject.

## Что видно в игре

Башня начинает со 100 HP. При контакте врага с её триггером HP уменьшается на 10, а враг удаляется через ECB. Текст на экране показывает `Здоровье башни: текущее/максимальное`. Когда HP станет меньше максимума, можно один раз за запуск нажать «Починить башню (+20)». HP не превышает максимум. При 0 HP текст здоровья показывает «Башня разрушена», ремонт уже недоступен, а отдельная панель показывает «Поражение! Башня уничтожена». Игра не перезапускается и не останавливается автоматически.

Начальные 12 врагов по прежнему создаёт существующий ECS-спавнер с интервалом. Отдельной кнопки для добавления волны нет. Полноценную систему нескольких волн, монет и построек добавим в следующих этапах проекта.

## Термины

- **Entity:** башня и враги после запекания или создания префаба в ECS-мире.
- **Component:** данные без игровой логики. `TowerHealth` содержит два целых числа — текущее и максимальное HP.
- **Baker:** переводит настройки `TowerAuthoring` из SubScene в компоненты entity башни.
- **System и Job:** код ECS, который обрабатывает события триггера. `RemoveAtTowerSystem` запускает `RemoveAtTowerJob` после физики.
- **EntityCommandBuffer (ECB):** записывает команду удаления врага; ECS выполнит её в конце фиксированного шага. HP меняется прямо в job, потому что компонент уже существует.
- **Canvas / MonoBehaviour:** обычный UI вне SubScene. Он читает одно значение ECS через `EntityManager` и пишет его в `Text`.
- **EntityQuery:** находит единственную башню по `TowerTarget` и `TowerHealth`. Кнопка и текст используют этот запрос.
- **Событие/делегат:** `TowerDefeatEvent.Defeated` позволяет ECS сообщить обычному `MonoBehaviour` о редком событии поражения. Подписка происходит в `OnEnable`, отписка — в `OnDisable`.

## Порядок работы

1. `TowerBaker` создаёт у башни `TowerTarget` и `TowerHealth` со значением 100/100.
2. Когда враг входит в триггер башни, физика создаёт `TriggerEvent`.
3. `RemoveAtTowerJob` уменьшает HP на 10 и записывает в ECB удаление врага.
4. `TowerHealthPanel.Update` читает HP башни и обновляет текст Canvas.
5. Нажатие кнопки вызывает `TowerHealthPanel.RepairTower`: метод добавляет до 20 HP и записывает результат в компонент башни.
6. После фиксированного шага `TowerDefeatSystem` ждёт завершения Jobs и проверяет HP. При нуле она один раз вызывает `TowerDefeatEvent.Raise()` из обычного `OnUpdate`, без Burst.
7. `TowerDefeatPanel` получает событие и включает заранее скрытый UI-объект `Defeat Panel`.

Сцена `Assets/Scenes/SampleScene.unity` содержит `Tower Health Canvas`, его текст, кнопку и скрытую `Defeat Panel` с `Defeat Text`; событие кнопки **On Click** связано с `RepairTower`. Оба UI-скрипта находятся на Canvas. Башня находится в `Gameplay` SubScene.

## Полные листинги изменённого кода

### `Assets/Scripts/Components/TowerHealth.cs`

Данные здоровья башни. Current — текущее HP, Max — максимум.

```csharp
using Unity.Entities;

public struct TowerHealth : IComponentData
{
    public int Current;
    public int Max;
}
```

### `Assets/Scripts/Authoring/TowerAuthoring.cs`

При запекании башня получает TowerTarget и TowerHealth. MaxHealth задаётся в Inspector.

```csharp
using Unity.Entities;
using UnityEngine;

public class TowerAuthoring : MonoBehaviour
{
    public int MaxHealth = 100;
}

class TowerBaker : Baker<TowerAuthoring>
{
    public override void Bake(TowerAuthoring authoring)
    {
        var entity = GetEntity(TransformUsageFlags.Dynamic);
        AddComponent<TowerTarget>(entity);
        var maxHealth = Mathf.Max(1, authoring.MaxHealth);
        AddComponent(entity, new TowerHealth { Current = maxHealth, Max = maxHealth });
    }
}
```

### `Assets/Scripts/Systems/RemoveAtTowerSystem.cs`

После физики система получает события входа врага в триггер башни. Job снимает 10 HP и записывает удаление врага в EntityCommandBuffer.

```csharp
using Unity.Burst;
using Unity.Collections;
using Unity.Entities;
using Unity.Physics;
using Unity.Physics.Systems;
using Unity.Mathematics;

[UpdateInGroup(typeof(FixedStepSimulationSystemGroup))]
[UpdateAfter(typeof(PhysicsSystemGroup))]
public partial struct RemoveAtTowerSystem : ISystem
{
    [BurstCompile]
    struct RemoveAtTowerJob : ITriggerEventsJob
    {
        [ReadOnly] public ComponentLookup<TowerTarget> Towers;
        [ReadOnly] public ComponentLookup<MoveSpeed> Enemies;
        public ComponentLookup<TowerHealth> Health;
        public EntityCommandBuffer CommandBuffer;

        public void Execute(TriggerEvent triggerEvent)
        {
            var a = triggerEvent.EntityA;
            var b = triggerEvent.EntityB;
            if (Towers.HasComponent(a) && Enemies.HasComponent(b))
                DamageTower(a, b);
            else if (Towers.HasComponent(b) && Enemies.HasComponent(a))
                DamageTower(b, a);
        }

        void DamageTower(Entity tower, Entity enemy)
        {
            var health = Health[tower];
            health.Current = math.max(0, health.Current - 10);
            Health[tower] = health;
            CommandBuffer.DestroyEntity(enemy);
        }
    }

    public void OnCreate(ref SystemState state)
    {
        state.RequireForUpdate<TowerTarget>();
        state.RequireForUpdate<TowerHealth>();
        state.RequireForUpdate<MoveSpeed>();
        state.RequireForUpdate<SimulationSingleton>();
        state.RequireForUpdate<EndFixedStepSimulationEntityCommandBufferSystem.Singleton>();
    }

    [BurstCompile]
    public void OnUpdate(ref SystemState state)
    {
        var ecb = SystemAPI.GetSingleton<EndFixedStepSimulationEntityCommandBufferSystem.Singleton>()
            .CreateCommandBuffer(state.WorldUnmanaged);
        var job = new RemoveAtTowerJob
        {
            Towers = SystemAPI.GetComponentLookup<TowerTarget>(true),
            Enemies = SystemAPI.GetComponentLookup<MoveSpeed>(true),
            Health = SystemAPI.GetComponentLookup<TowerHealth>(),
            CommandBuffer = ecb
        };
        state.Dependency = job.Schedule(SystemAPI.GetSingleton<SimulationSingleton>(), state.Dependency);
    }
}
```

### `Assets/Scripts/TowerHealthPanel.cs`

Обычный MonoBehaviour на Canvas читает HP из ECS и показывает его в Text. Кнопка вызывает RepairTower: один раз за запуск возвращает 20 HP и записывает новое значение в ECS.

```csharp
using Unity.Entities;
using UnityEngine;
using UnityEngine.UI;

public class TowerHealthPanel : MonoBehaviour
{
    const int RepairAmount = 20;

    [SerializeField] Text healthText;
    [SerializeField] Button repairButton;

    World _world;
    EntityQuery _towerQuery;
    bool _queryCreated;
    bool _repairUsed;

    void Update()
    {
        if (!EnsureTower())
        {
            healthText.text = "Загрузка башни...";
            repairButton.interactable = false;
            return;
        }

        var tower = _towerQuery.GetSingletonEntity();
        var health = _world.EntityManager.GetComponentData<TowerHealth>(tower);
        healthText.text = health.Current == 0
            ? "Башня разрушена"
            : $"Здоровье башни: {health.Current}/{health.Max}";
        repairButton.interactable = !_repairUsed && health.Current > 0 && health.Current < health.Max;
    }

    bool EnsureTower()
    {
        var world = World.DefaultGameObjectInjectionWorld;
        if (world == null || !world.IsCreated)
            return false;

        if (!_queryCreated || _world != world)
        {
            if (_queryCreated && _world != null && _world.IsCreated)
                _towerQuery.Dispose();
            _world = world;
            _towerQuery = world.EntityManager.CreateEntityQuery(
                ComponentType.ReadOnly<TowerTarget>(),
                ComponentType.ReadWrite<TowerHealth>());
            _queryCreated = true;
        }

        return _towerQuery.CalculateEntityCount() == 1;
    }

    // Called by the Button On Click event in the Inspector.
    public void RepairTower()
    {
        if (_repairUsed || !EnsureTower())
            return;

        var tower = _towerQuery.GetSingletonEntity();
        var health = _world.EntityManager.GetComponentData<TowerHealth>(tower);
        if (health.Current <= 0 || health.Current >= health.Max)
            return;

        health.Current = Mathf.Min(health.Max, health.Current + RepairAmount);
        _world.EntityManager.SetComponentData(tower, health);
        _repairUsed = true;
        healthText.text = $"Здоровье башни: {health.Current}/{health.Max}";
        repairButton.interactable = false;
    }

    void OnDestroy()
    {
        if (_queryCreated && _world != null && _world.IsCreated)
            _towerQuery.Dispose();
    }
}
```

### `Assets/Scripts/Systems/TowerDefeatSystem.cs`

Эта система работает после `FixedStepSimulationSystemGroup`, то есть после физики и `RemoveAtTowerSystem`. `state.Dependency.Complete()` дожидается Job, который мог изменить HP. Поле `_eventSent` запоминает, что событие уже отправлено: при нуле HP повторного вызова не будет. `OnUpdate` не помечен `[BurstCompile]`, поэтому вызов управляемого делегата здесь допустим. Внутри `ITriggerEventsJob` делегат не вызывается.

```csharp
using System;
using Unity.Entities;

public static class TowerDefeatEvent
{
    public static event Action Defeated;

    public static void Raise()
    {
        Defeated?.Invoke();
    }
}

[UpdateInGroup(typeof(SimulationSystemGroup))]
[UpdateAfter(typeof(FixedStepSimulationSystemGroup))]
public partial struct TowerDefeatSystem : ISystem
{
    bool _eventSent;

    public void OnCreate(ref SystemState state)
    {
        state.RequireForUpdate<TowerHealth>();
    }

    public void OnUpdate(ref SystemState state)
    {
        // The trigger job writes TowerHealth during the fixed step.
        state.Dependency.Complete();

        if (_eventSent || SystemAPI.GetSingleton<TowerHealth>().Current > 0)
            return;

        _eventSent = true;
        TowerDefeatEvent.Raise();
    }
}
```

### `Assets/Scripts/TowerDefeatPanel.cs`

Этот скрипт находится на активном Canvas. Сам объект `Defeat Panel` выключен в сцене и ещё раз скрывается в `Awake`. `OnEnable` подписывается на событие, `OnDisable` отписывается. Когда ECS вызывает событие, `ShowDefeat` включает панель. Скрипт не ищет ECS-мир и не читает HP через `EntityManager`.

```csharp
using UnityEngine;

public class TowerDefeatPanel : MonoBehaviour
{
    [SerializeField] GameObject defeatPanel;

    void Awake()
    {
        defeatPanel.SetActive(false);
    }

    void OnEnable()
    {
        TowerDefeatEvent.Defeated += ShowDefeat;
    }

    void OnDisable()
    {
        TowerDefeatEvent.Defeated -= ShowDefeat;
    }

    void ShowDefeat()
    {
        defeatPanel.SetActive(true);
    }
}
```

### Чем два способа Entity → GameObject отличаются

`TowerHealthPanel.Update` каждый кадр **спрашивает ECS**, сколько сейчас HP, через `EntityManager`: это удобно для постоянно меняющегося числа. `TowerDefeatSystem` **сама сообщает UI** о редком событии при достижении нуля: это удобно для однократного показа панели. В обоих случаях данные исходят из ECS, но направление вызова различается.

## Как коротко объяснить преподавателю

> В пятой практической я сделала три сценария связи. Текст Canvas читает HP башни из ECS через EntityManager. Кнопка ремонта записывает новое HP обратно в ECS. Когда HP становится нулевым, отдельная ECS-система один раз вызывает событие, на которое подписан MonoBehaviour панели поражения. Вызов события происходит после Job и вне Burst. Урон и удаление врага по прежнему обрабатываются в ECS.
