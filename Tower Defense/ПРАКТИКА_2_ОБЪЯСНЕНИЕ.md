# Вторая практическая ECS: объяснение проекта и полный код

Это учебное объяснение **текущей версии** проекта Tower Defense. Сначала прочитай три требования задания и общий порядок работы, затем — разделы с кодом. Каждый листинг ниже взят целиком из названного файла проекта. В конце есть ответы на вопросы для защиты.

## 1. Что требует задание и где это сделано

| Пункт задания | Что нужно показать | Где находится в проекте |
|---|---|---|
| 1. Спавн и удаление entity через `EntityCommandBuffer`; префабы в Singleton-компоненте | Враги создаются и удаляются командами ECB. Ссылка на префаб лежит в одном ECS-компоненте-хранилище. | `EnemyPrefabStore`, `EnemySpawnerAuthoring`, `EnemySpawnerSystem`, `RemoveAtTowerSystem` |
| 2. Blob **или** DynamicBuffer | Достаточно одного способа хранения. Здесь выбран динамический список запросов на появление врагов. | `EnemySpawnRequest`, `EnemySpawnerAuthoring`, `EnemySpawnerSystem` |
| 3. `Unity.Mathematics.Random` | Случайный элемент игры. | Случайное смещение места появления в `EnemySpawnerSystem` |

**Что видно в Game:** после Play появляются 12 врагов с интервалом 0,7 секунды. Они стартуют около спавнера с небольшим случайным разбросом, идут к башне, временами отдыхают из-за стамины и исчезают возле башни. Когда очередь закончилась, новые враги не появляются.

В сцене `Assets/Scenes/SampleScene/Gameplay.unity` на объекте `Spawner` указан префаб `Assets/Prefabs/Enemy.prefab`, `EnemyCount = 12`, `SpawnInterval = 0.7`, `SpawnSpread = 1.2`. На `Tower` стоит `TowerAuthoring`. Главная сцена `SampleScene` автоматически загружает `Gameplay` SubScene.

## 2. Минимальная теория перед кодом

**Entity** — отдельная ECS-сущность с идентификатором. В игре отдельными entity становятся башня, спавнер и каждый созданный враг.

**Component** — данные или метка сущности. Например, `EnemyPrefabStore` хранит ссылку на префаб, `MoveSpeed` хранит скорость, `TowerTarget` помечает башню как цель.

**System** — код, который находит entity с нужными компонентами и выполняет действие. Например, `EnemySpawnerSystem` создаёт врагов, `RemoveAtTowerSystem` удаляет дошедших до башни.

**Authoring** — обычный `MonoBehaviour` с полями для Inspector. **Baker** — класс, который при подготовке ECS-данных переносит эти настройки в ECS-компоненты. Например, из поля `Prefab` у GameObject спавнера Baker делает компонент со ссылкой на ECS-префаб. Это и называется «запеканием».

**Префаб** — шаблон врага. Спавнер не хранит 12 готовых врагов. Он хранит ссылку на шаблон, из которого система создаёт 12 отдельных entity по очереди.

## 3. Пункт 1: Singleton-хранилище префаба

### 3.1. Что такое Singleton в этом проекте

**Singleton-компонент** — обычный `IComponentData`, который в текущем ECS-мире имеется **ровно у одной entity**. Здесь такая entity — спавнер. Поэтому система может вызвать `SystemAPI.GetSingleton<EnemyPrefabStore>()` и сразу получить ссылку на префаб.

`Singleton` — не специальный интерфейс, который надо написать в объявлении компонента. Это свойство **текущих данных мира**: компонент есть ровно в одном экземпляре. Если бы в сцене не было такого компонента или он оказался сразу у двух entity, `GetSingleton` не смог бы вернуть однозначный результат. В текущей сцене один спавнер.

`EnemyPrefabStore` хранит `Entity Enemy`. Здесь `Entity` — ссылка на запечённый ECS-префаб, а не имя файла и не живой враг.

**Файл: `Assets/Scripts/Components/EnemyPrefabStore.cs`. Полный листинг:**

```csharp
using Unity.Entities;

/// <summary>Единственное хранилище префаба врага в ECS-мире.</summary>
public struct EnemyPrefabStore : IComponentData
{
    public Entity Enemy;
}
```

### 3.2. Как префаб попадает в хранилище

На GameObject `Spawner` в SubScene висит `EnemySpawnerAuthoring`. В его поле `Prefab` в Inspector назначен `Enemy.prefab`. В `EnemySpawnerBaker` строка `GetEntity(authoring.Prefab, TransformUsageFlags.Dynamic)` получает ECS-ссылку на этот префаб. Затем `AddComponent` записывает ссылку в `EnemyPrefabStore` на entity спавнера.

Этот же Baker создаёт `EnemySpawner` с параметрами появления и добавляет буфер запросов волны. Полный листинг нужен сразу для пунктов 1 и 2.

**Файл: `Assets/Scripts/Authoring/EnemySpawnerAuthoring.cs`. Полный листинг:**

```csharp
using Unity.Entities;
using UnityEngine;

public class EnemySpawnerAuthoring : MonoBehaviour
{
    public GameObject Prefab;
    public int EnemyCount = 12;
    public float SpawnInterval = 0.7f;
    public float SpawnSpread = 1.2f;
}

class EnemySpawnerBaker : Baker<EnemySpawnerAuthoring>
{
    public override void Bake(EnemySpawnerAuthoring authoring)
    {
        if (authoring.Prefab == null)
            return;

        var entity = GetEntity(TransformUsageFlags.Dynamic);
        AddComponent(entity, new EnemySpawner
        {
            NextSpawnTime = 0f,
            SpawnSpread = Mathf.Max(0f, authoring.SpawnSpread)
        });

        AddComponent(entity, new EnemyPrefabStore
        {
            Enemy = GetEntity(authoring.Prefab, TransformUsageFlags.Dynamic)
        });

        var requests = AddBuffer<EnemySpawnRequest>(entity);
        var count = Mathf.Max(0, authoring.EnemyCount);
        var interval = Mathf.Max(0.05f, authoring.SpawnInterval);
        for (var i = 0; i < count; i++)
            requests.Add(new EnemySpawnRequest { DelayBeforeNext = interval });
    }
}
```

Разбор важных строк этого файла:

- `public GameObject Prefab` — поле Inspector, куда назначается префаб врага.
- `EnemyCount`, `SpawnInterval`, `SpawnSpread` — настройки количества, интервала и диапазона случайного смещения.
- `if (authoring.Prefab == null) return` — без префаба ECS-компоненты спавнера не создаются.
- `GetEntity(TransformUsageFlags.Dynamic)` — ECS-сущность самого GameObject спавнера, с доступной позицией.
- `AddComponent(... EnemyPrefabStore ...)` — кладёт ECS-ссылку на префаб в единственное хранилище.
- `Mathf.Max` — не даёт отрицательному количеству или разбросу и слишком маленькому интервалу испортить настройки.
- `AddBuffer<EnemySpawnRequest>(entity)` — создаёт изменяемую очередь на той же entity спавнера.

### 3.3. Данные времени и разброса

`EnemySpawner` не хранит префаб: для него выделен отдельный `EnemyPrefabStore`. `NextSpawnTime` — ближайший момент появления в секундах игрового времени, `SpawnSpread` — размер случайного смещения от позиции спавнера.

**Файл: `Assets/Scripts/Components/EnemySpawner.cs`. Полный листинг:**

```csharp
using Unity.Entities;

public struct EnemySpawner : IComponentData
{
    public float NextSpawnTime;
    public float SpawnSpread;
}
```

## 4. Пункт 1: создание и удаление через EntityCommandBuffer

### 4.1. Что такое ECB и зачем он нужен

`EntityCommandBuffer`, или **ECB**, — буфер **команд на изменение ECS-мира**. Например: создать entity, удалить entity, добавить или установить компонент. Система записывает команду сейчас; буфер воспроизводит её позднее в установленный момент. Это удобно, когда изменения состава entity нужно отложить до безопасного момента, особенно во время перебора сущностей.

В этом проекте используется `EndSimulationEntityCommandBufferSystem.Singleton`. Он выдаёт ECB, команды которого воспроизводятся **в конце шага Simulation**. Важно: `ecb.Instantiate` и `ecb.DestroyEntity` в системах ниже записывают команды. Фактическое создание и удаление происходят при воспроизведении буфера.

**Не путай:** `EnemyPrefabStore` — Singleton-хранилище *данных префаба*. `EndSimulationEntityCommandBufferSystem.Singleton` — предоставляемый Unity доступ к системе, которая воспроизведёт ECB. Это разные Singleton.

### 4.2. Система появления врагов

Ниже полный код. За каждое срабатывание после проверки времени система берёт один запрос из очереди, считывает префаб из Singleton-хранилища, выбирает случайную позицию, записывает в ECB команды создать врага и назначить ему трансформ, затем убирает использованный запрос.

**Файл: `Assets/Scripts/Systems/EnemySpawnerSystem.cs`. Полный листинг:**

```csharp
using Unity.Entities;
using Unity.Mathematics;
using Unity.Transforms;

public partial struct EnemySpawnerSystem : ISystem
{
    Random _random;

    public void OnCreate(ref SystemState state)
    {
        state.RequireForUpdate<EnemySpawner>();
        state.RequireForUpdate<EnemyPrefabStore>();
        state.RequireForUpdate<EnemySpawnRequest>();
        state.RequireForUpdate<EndSimulationEntityCommandBufferSystem.Singleton>();
        _random = Random.CreateFromIndex((uint)System.DateTime.UtcNow.Ticks);
    }

    public void OnUpdate(ref SystemState state)
    {
        var requests = SystemAPI.GetSingletonBuffer<EnemySpawnRequest>();
        if (requests.Length == 0)
            return;

        var spawner = SystemAPI.GetSingletonRW<EnemySpawner>();
        if (SystemAPI.Time.ElapsedTime < spawner.ValueRO.NextSpawnTime)
            return;

        var prefab = SystemAPI.GetSingleton<EnemyPrefabStore>().Enemy;
        var spawnEntity = SystemAPI.GetSingletonEntity<EnemySpawner>();
        var transform = SystemAPI.GetComponent<LocalTransform>(spawnEntity);
        transform.Position.x += _random.NextFloat(-spawner.ValueRO.SpawnSpread, spawner.ValueRO.SpawnSpread);
        transform.Position.z += _random.NextFloat(-spawner.ValueRO.SpawnSpread, spawner.ValueRO.SpawnSpread);

        var ecb = SystemAPI.GetSingleton<EndSimulationEntityCommandBufferSystem.Singleton>()
            .CreateCommandBuffer(state.WorldUnmanaged);
        var enemy = ecb.Instantiate(prefab);
        ecb.SetComponent(enemy, transform);

        spawner.ValueRW.NextSpawnTime = (float)SystemAPI.Time.ElapsedTime + requests[0].DelayBeforeNext;
        requests.RemoveAt(0);
    }
}
```

Разбор `OnCreate`:

- `RequireForUpdate<...>()` означает: система не выполняет `OnUpdate`, пока в мире нет требуемых ECS-компонентов и ECB Singleton.
- `_random` — состояние генератора `Unity.Mathematics.Random`. Оно сохраняется в системе между кадрами.

Разбор `OnUpdate` по порядку:

1. `GetSingletonBuffer<EnemySpawnRequest>()` получает очередь на единственном спавнере. Если она пустая, делать нечего.
2. `GetSingletonRW<EnemySpawner>()` получает настройки и изменяемое время следующего появления. `ElapsedTime < NextSpawnTime` останавливает выполнение до нужного момента.
3. `GetSingleton<EnemyPrefabStore>().Enemy` читает ECS-префаб из хранилища. **Вот непосредственное использование Singleton для спавна.**
4. `GetSingletonEntity<EnemySpawner>()` находит entity спавнера, а `GetComponent<LocalTransform>` берёт его положение.
5. Два вызова `_random.NextFloat(...)` сдвигают X и Z позиции появления независимо друг от друга.
6. `CreateCommandBuffer(...)` получает ECB конца симуляции. `ecb.Instantiate(prefab)` записывает создание врага. `ecb.SetComponent(enemy, transform)` записывает ему случайную позицию.
7. `NextSpawnTime` переносится на `DelayBeforeNext` секунд вперёд. `requests.RemoveAt(0)` удаляет использованный запрос из очереди.

Переменная `enemy`, возвращённая `ecb.Instantiate`, — временная ссылка для последующих команд **того же ECB**. Поэтому можно сразу записать `ecb.SetComponent(enemy, transform)`, хотя фактическое создание произойдёт при воспроизведении команд.

`requests.RemoveAt(0)` меняет содержимое DynamicBuffer, а не создаёт и не удаляет entity. Требование использовать ECB для спавна и удаления entity здесь соблюдено: эти операции выполняются только через `ecb.Instantiate` и `ecb.DestroyEntity`.

### 4.3. Система удаления врагов у башни

Эта система получает позицию единственной башни с меткой `TowerTarget`, перебирает сущности с `LocalTransform` и `MoveSpeed`, сравнивает горизонтальное расстояние с `ReachDistance` и записывает удаление дошедших врагов в ECB.

**Файл: `Assets/Scripts/Systems/RemoveAtTowerSystem.cs`. Полный листинг:**

```csharp
using Unity.Burst;
using Unity.Entities;
using Unity.Mathematics;
using Unity.Transforms;

/// <summary>Удаляет врагов, дошедших до башни.</summary>
[UpdateAfter(typeof(MoveToTowerSystem))]
public partial struct RemoveAtTowerSystem : ISystem
{
    public void OnCreate(ref SystemState state)
    {
        state.RequireForUpdate<TowerTarget>();
        state.RequireForUpdate<MoveSpeed>();
        state.RequireForUpdate<EndSimulationEntityCommandBufferSystem.Singleton>();
    }

    [BurstCompile]
    public void OnUpdate(ref SystemState state)
    {
        var tower = SystemAPI.GetSingletonEntity<TowerTarget>();
        var towerPosition = SystemAPI.GetComponent<LocalTransform>(tower).Position;
        var ecb = SystemAPI.GetSingleton<EndSimulationEntityCommandBufferSystem.Singleton>()
            .CreateCommandBuffer(state.WorldUnmanaged);

        foreach (var (transform, speed, entity) in
                 SystemAPI.Query<RefRO<LocalTransform>, RefRO<MoveSpeed>>().WithEntityAccess())
        {
            var offset = towerPosition.xz - transform.ValueRO.Position.xz;
            var reach = speed.ValueRO.ReachDistance;
            if (math.lengthsq(offset) <= reach * reach)
                ecb.DestroyEntity(entity);
        }
    }
}
```

Важные детали:

- `[UpdateAfter(typeof(MoveToTowerSystem))]` задаёт порядок: сначала враг сдвигается, потом проверяется достижение башни.
- `.WithEntityAccess()` даёт в цикле `entity` — конкретную сущность, которую надо удалить.
- `towerPosition.xz` и `transform.ValueRO.Position.xz` берут горизонтальные координаты X и Z. Высота Y в проверке не участвует.
- `math.lengthsq(offset) <= reach * reach` сравнивает квадрат расстояния без вычисления квадратного корня.
- `ecb.DestroyEntity(entity)` записывает удаление именно найденного врага. Башня не подходит под запрос, потому что у неё нет `MoveSpeed`.

В `Enemy.prefab` установлен `ReachDistance = 1.5`, чтобы враг исчезал рядом с видимой башней, а не глубоко в её центре.

## 5. Пункт 2: DynamicBuffer

### 5.1. Почему выбран он, а не Blob

Задание требует **Blob или DynamicBuffer**, оба сразу не нужны. Blob подходит для данных, которые после создания не меняются. Здесь нужна **изменяемая очередь**: перед стартом в ней 12 запросов, после каждого появления один запрос удаляется. Поэтому выбран `DynamicBuffer`.

`DynamicBuffer<T>` — список однотипных элементов, прикреплённый к entity как ECS-компонент. Тип одного элемента обязан реализовывать `IBufferElementData`. Наш элемент — один запрос на появление врага:

**Файл: `Assets/Scripts/Components/EnemySpawnRequest.cs`. Полный листинг:**

```csharp
using Unity.Entities;

/// <summary>Один враг в очереди волны.</summary>
public struct EnemySpawnRequest : IBufferElementData
{
    public float DelayBeforeNext;
}
```

`DelayBeforeNext` — задержка перед **следующим** появлением после обработки этой записи. В Baker каждый из 12 элементов получает интервал из Inspector. Первое появление возможно сразу, потому что `NextSpawnTime` начинается с нуля; после него система назначает следующий момент появления.

### 5.2. Жизнь очереди

```text
До Play / после baking:  [запрос, запрос, ... ещё 10 запросов]  → 12
После первого спавна:  [запрос, запрос, ... ещё 9 запросов]   → 11
...
После двенадцатого:   []                                  → 0
```

Очередь создаётся `AddBuffer<EnemySpawnRequest>(entity)` в `EnemySpawnerBaker` и заполняется циклом `for`. Во время игры `EnemySpawnerSystem` читает первый элемент и вызывает `requests.RemoveAt(0)`. Когда `Length == 0`, новых врагов больше нет. Пустой буфер при этом остаётся компонентом entity спавнера; удаляются только его элементы.

**DynamicBuffer не то же самое, что EntityCommandBuffer.** Первый хранит данные волны. Второй хранит команды на изменения ECS-мира.

## 6. Пункт 3: Unity.Mathematics.Random

В `EnemySpawnerSystem` поле `_random` имеет тип `Unity.Mathematics.Random`. При создании системы генератор получает начальное значение — **seed**:

```csharp
_random = Random.CreateFromIndex((uint)System.DateTime.UtcNow.Ticks);
```

Каждый вызов `NextFloat(min, max)` даёт очередное псевдослучайное число в диапазоне. Генератор — структура со своим состоянием; последовательность зависит от seed. В этой работе seed берётся из текущего времени, чтобы при новых запусках получались разные последовательности.

```csharp
transform.Position.x += _random.NextFloat(-spawner.ValueRO.SpawnSpread, spawner.ValueRO.SpawnSpread);
transform.Position.z += _random.NextFloat(-spawner.ValueRO.SpawnSpread, spawner.ValueRO.SpawnSpread);
```

Если `SpawnSpread = 1.2`, каждый враг появляется на случайном расстоянии по X и Z в пределах от `-1.2` до `+1.2` относительно спавнера. Случайность влияет **только на точку появления**: цель остаётся башней. Это прямо выполняет пункт 3.

## 7. Как всё работает вместе — от нажатия Play до конца волны

1. Unity загружает `SampleScene` и `Gameplay` SubScene.
2. Baker спавнера подготавливает entity спавнера: компонент времени, Singleton-хранилище префаба и DynamicBuffer с 12 запросами.
3. Baker башни помечает её entity компонентом `TowerTarget`. Baker префаба врага подготавливает его скорость, стамину и разрешение двигаться.
4. `EnemySpawnerSystem` дожидается нужного времени, случайно выбирает место, записывает создание врага в ECB и сокращает очередь на один элемент.
5. В конце шага симуляции Unity воспроизводит ECB; появляется новая entity врага.
6. `StaminaSystem` и `MoveToTowerSystem` из первой практической управляют паузами и движением к текущему положению башни.
7. `RemoveAtTowerSystem` после движения проверяет расстояние и записывает удаление дошедшего врага в ECB. В конце шага симуляции он исчезает.
8. После 12 созданий очередь пустеет. Когда все дошли до башни, на сцене не остаётся врагов.

Ниже — полные листинги поддерживающего кода. Он в основном относится к первой практической, но без него нельзя понять, откуда система удаления берёт цель и дистанцию остановки и почему враги вообще движутся.

## 8. Связанные скрипты первой практической

### 8.1. Башня: кто является целью

### 8.2. Враг: начальные компоненты

Поля `EnemyAuthoring` можно менять в Inspector префаба. Baker переносит их в ECS-компоненты `MoveSpeed`, `Stamina` и включённый `CanMove`. На префабе сохранены скорость `2`, максимальная стамина `4`, расход `1.6`, восстановление `1.1` и дистанция остановки `1.5`. Значения в коде — только значения по умолчанию для новых компонентов.

**Файл: `Assets/Scripts/Authoring/EnemyAuthoring.cs`. Полный листинг:**

```csharp
using Unity.Entities;
using UnityEngine;

public class EnemyAuthoring : MonoBehaviour
{
    public float Speed = 3f;
    public float ReachDistance = 0.35f;
    public float MaxStamina = 2f;
    public float StaminaDrainPerSecond = 2.5f;
    public float StaminaRegenPerSecond = 2f;
}

class EnemyBaker : Baker<EnemyAuthoring>
{
    public override void Bake(EnemyAuthoring authoring)
    {
        var entity = GetEntity(TransformUsageFlags.Dynamic);

        AddComponent(entity, new MoveSpeed
        {
            Value = authoring.Speed,
            ReachDistance = authoring.ReachDistance
        });
        AddComponent(entity, new Stamina
        {
            Current = authoring.MaxStamina,
            Max = authoring.MaxStamina,
            DrainPerSecond = authoring.StaminaDrainPerSecond,
            RegenPerSecond = authoring.StaminaRegenPerSecond,
            MinToMove = authoring.MaxStamina * 0.5f
        });
        AddComponent<CanMove>(entity);
        SetComponentEnabled<CanMove>(entity, true);
    }
}
```

### 8.3. Движение и восстановление стамины

`MoveToTowerSystem` каждый кадр берёт текущую позицию башни, двигает подходящих врагов по горизонтали и уменьшает стамину. Система удаления ориентируется на тот же `ReachDistance`. Препятствия здесь не обходятся: движение прямое.

**Файл: `Assets/Scripts/Systems/MoveToTowerSystem.cs`. Полный листинг:**

```csharp
using Unity.Burst;
using Unity.Entities;
using Unity.Mathematics;
using Unity.Transforms;

public partial struct MoveToTowerSystem : ISystem
{
    public void OnCreate(ref SystemState state)
    {
        state.RequireForUpdate<TowerTarget>();
        state.RequireForUpdate<MoveSpeed>();
    }

    [BurstCompile]
    public void OnUpdate(ref SystemState state)
    {
        var towerEntity = SystemAPI.GetSingletonEntity<TowerTarget>();
        var towerPosition = SystemAPI.GetComponent<LocalTransform>(towerEntity).Position;
        var deltaTime = SystemAPI.Time.DeltaTime;

        foreach (var (transform, speed, stamina) in
                 SystemAPI.Query<RefRW<LocalTransform>, RefRO<MoveSpeed>, RefRW<Stamina>>()
                     .WithAll<CanMove>())
        {
            var position = transform.ValueRO.Position;
            var target = new float3(towerPosition.x, position.y, towerPosition.z);
            var offset = target - position;
            var distance = math.length(offset);
            if (distance <= speed.ValueRO.ReachDistance)
                continue;

            var direction = offset / distance;
            var step = math.min(speed.ValueRO.Value * deltaTime, distance - speed.ValueRO.ReachDistance);
            transform.ValueRW.Position = position + direction * step;
            transform.ValueRW.Rotation = quaternion.LookRotationSafe(direction, math.up());
            stamina.ValueRW.Current = math.max(
                0f,
                stamina.ValueRO.Current - stamina.ValueRO.DrainPerSecond * deltaTime);
        }
    }
}
```

`StaminaSystem` выполняется перед движением. Она выключает `CanMove` при нулевой стамине, восстанавливает её во время отдыха и снова разрешает движение после достижения `MinToMove`.

**Файл: `Assets/Scripts/Systems/StaminaSystem.cs`. Полный листинг:**

```csharp
using Unity.Burst;
using Unity.Entities;
using Unity.Mathematics;

[UpdateBefore(typeof(MoveToTowerSystem))]
public partial struct StaminaSystem : ISystem
{
    public void OnCreate(ref SystemState state)
    {
        state.RequireForUpdate<Stamina>();
    }

    [BurstCompile]
    public void OnUpdate(ref SystemState state)
    {
        var deltaTime = SystemAPI.Time.DeltaTime;

        foreach (var (stamina, entity) in SystemAPI.Query<RefRW<Stamina>>().WithEntityAccess())
        {
            var canMove = SystemAPI.IsComponentEnabled<CanMove>(entity);

            if (canMove && stamina.ValueRO.Current <= 0f)
            {
                SystemAPI.SetComponentEnabled<CanMove>(entity, false);
                canMove = false;
            }

            if (!canMove)
            {
                stamina.ValueRW.Current = math.min(
                    stamina.ValueRO.Max,
                    stamina.ValueRO.Current + stamina.ValueRO.RegenPerSecond * deltaTime);

                if (stamina.ValueRO.Current >= stamina.ValueRO.MinToMove)
                    SystemAPI.SetComponentEnabled<CanMove>(entity, true);
            }
        }
    }
}
```

## 9. Частые вопросы на защите

**Почему `EnemyPrefabStore` называется Singleton?** В текущем мире он есть у одной entity спавнера. Метод `GetSingleton` получает его без перебора. Тип компонента сам по себе не ограничивает число экземпляров.

**Почему хранилище префаба отдельно от спавнера?** Так требование о Singleton-хранилище видно прямо в коде. `EnemySpawner` хранит время и разброс, `EnemyPrefabStore` — ссылку на префаб.

**Почему `ecb.Instantiate`, а не `EntityManager.Instantiate`?** Во второй практической создание entity должно выполняться через EntityCommandBuffer. Команда записывается в системе и воспроизводится в конце симуляции.

**Почему `ecb.DestroyEntity`, а не прямое удаление?** По той же причине; к тому же система удаляет сущности, перебирая их, и откладывание структурного изменения удобно для такого цикла.

**Что хранит DynamicBuffer?** 12 записей-запросов волны. После каждого появления одна запись удаляется; это изменяемые данные, поэтому DynamicBuffer подходит лучше Blob.

**Это две разные очереди?** Да. DynamicBuffer — очередь данных «кого ещё выпустить». EntityCommandBuffer — очередь действий «создать/удалить entity».

**Что случайно?** Только X и Z появления врагов. Используется `Unity.Mathematics.Random`, а не `UnityEngine.Random` при выполнении системы.

**Почему враги исчезают возле башни?** `RemoveAtTowerSystem` сравнивает расстояние до башни с `MoveSpeed.ReachDistance` и записывает удаление в ECB.

**Есть ли урон башне, поиск пути, анимация и много волн?** Нет. Для второй практической они не требуются. Сейчас одна мини-волна и прямое движение к башне.

## 10. Короткое объяснение для преподавателя

> Во второй практической я добавила одну волну из 12 врагов. Ссылка на ECS-префаб врага хранится в единственном компоненте `EnemyPrefabStore` на entity спавнера. Очередь появления — `DynamicBuffer<EnemySpawnRequest>`; после каждого появления из неё удаляется один элемент. `EnemySpawnerSystem` через `Unity.Mathematics.Random` задаёт случайный разброс позиции и записывает создание врага в `EntityCommandBuffer`. Когда враг доходит до башни, `RemoveAtTowerSystem` записывает его удаление в ECB. Движение к башне и стамина остались из первой практической.

## 11. Как самостоятельно проверить в Unity

1. Открой `Assets/Scenes/SampleScene.unity` и убедись, что `Gameplay` SubScene загружается.
2. В SubScene выбери `Spawner`: в Inspector должен быть назначен `Enemy.prefab`, число врагов — 12, интервал — 0,7, разброс — 1,2.
3. Запусти Play: враги появляются по одному вокруг спавнера, идут к башне и исчезают рядом с ней.
4. Если нужно увидеть именно ECS-сущности и компоненты, открой окна Entities в Unity и переключи просмотр данных на Runtime Data, как показано в шпаргалке.
5. Если сдаёшь через Git, добавь новые `.cs` и `.meta` файлы в коммит: сейчас изменения проекта могут оставаться локальными.
